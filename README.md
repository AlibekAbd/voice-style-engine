# voice-style-engine

Снятие манеры переписки человека из Телеграма: из годовой выгрузки личных
чатов получается файл стиля — регистры общения, блоки речевых действий с
весами, цитаты, посчитанные признаки — и скилл, по которому агент пишет от
имени владельца и меняет манеру под собеседника.

Конвейер: выгрузка → отбор и батчи → разбор батчей моделью → классификация
собеседников → своды по регистрам → сборка файла стиля → обезличивание →
раскладка по скиллу → замер по отложенной выборке.

Модель — Gemini через REST. Все обращения к модели и все траты — в одном
модуле (`voice.analyse`), всё, что требует сессии Телеграма, — в другом
(`voice.collect`). Остальное — чистые правила без сети и денег.

## Установка

```
pip install -r requirements.txt
cp .env.example .env    # заполнить ключи
python -m pytest -q     # тесты не ходят ни в сеть, ни к ключам
```

## Чего здесь нет

Данных. Выгрузка, батчи, разборы, отложенная выборка живут в `out/` и под
гитигнором. Личная переписка наружу не уходит.

Файлов стиля и скилла. Они порождаются из переписки конкретного человека и
принадлежат ему.

Слоя отправки. `telegram.say` перед каждым исходящим сверяется с чёрным
списком ботов из модуля разведки основного проекта, которого в этом
репозитории нет; её тесты пропускаются, а сам конвейер снятия манеры только
читает.

## Конвейер одной картинкой

```
fetch → build → measure          сбор: выгрузка, отбор, батчи — бесплатно
   ↓
прогон-все                       разбор батчей моделью — ПЛАТНО (~$40 на 95 батчей)
   ↓
классификация → регистры         оси сведения — ПЛАТНО (меньше доллара)
   ↓
порции → своды → веса            сведение внутри регистров — ПЛАТНО (~$5)
   ↓
сборка файла → обезличивание     стиль.md и файлы выделенных — обезличивание ПЛАТНО (центы)
   ↓
skillpack.pack                   раскладка по скиллу — бесплатно
   ↓
замер по отложенной выборке      trial — ПЛАТНО (доллары)
```

Первый этап управляется CLI (`python -m tgservice.voice <шаг>`). Всё после
`прогон-все` запускается из Python: порядок вызовов описан в разделе
«Вторая половина».

## Задания агентам

Лежат в `tgservice/voice/prompts/` и правятся там. **Каждое правило в них
стоит за пойманной ошибкой** — не выкидывай, не проверив, что она не
вернётся.

| Файл | Кому | Зовётся из |
|---|---|---|
| `разбор.md` | агенту, читающему батч | `analyse.review` |
| `переспрос.md` | ему же, когда сверка нашла ошибки | `analyse.again` |
| `проверка.md` | второму агенту по утверждениям о манере | `analyse.audit` |
| `классификация.md` | агенту, раздающему классы отношений | `analyse.classify_all` |
| `классификация-проверка.md` | судье класса по сырой речи | `analyse.classify_check` |
| `свод.md` | агенту, сводящему порцию в свод | `analyse.merge_portion` |
| `обезличивание.md` | агенту, чистящему личные данные из цитат | `analyse.impersonate` |
| `смысл.md` | агенту, пересказывающему смысл ответа владельца | `analyse.meaning` |
| `ответ.md` | агенту, пишущему ответ от имени владельца | `analyse.reply_as_owner` |
| `замер-суд.md` | судье замера, сравнивающему два ответа | кодом не читается — судейский драйвер запускался отдельно; разбор его ответа умеют `trial.verdicts` и `trial.blind` |

## Порядок работ: сбор

```
python -m tgservice.voice fetch      # выгрузка, продолжается после обрыва
python -m tgservice.voice build      # отбор, отсев, отложенная выборка, батчи
python -m tgservice.voice measure    # замер
```

Сбоку, по надобности:

```
python -m tgservice.voice groups     # обзор всех групп: кого брать в сбор
python -m tgservice.voice lengths    # починка: дослать длительности в старую выгрузку
```

`fetch` ходит в Телеграм и помнит, какие чаты уже забрал. `build` и `measure`
считаются по тому, что лежит на диске. `build` переписывает всё, **кроме
отложенной выборки**: она отделяется один раз и не тасуется — старые обмены
уже видели агенты в прежних батчах, и пересбор сделал бы экзамен
недоказательным.

Ключи: `--days` меняет окно (без `--restart` не применяется и говорит об этом
вслух), `--restart` выгружает всё заново (восстановление по выгрузке при этом
не делается — иначе перезапуск в день исходной выгрузки был холостым),
`--only "имя,имя"` берёт только названные чаты.

**Сироты.** Файл чата, выпавшего из обхода (владелец убрал группу из
`groups_taken.json`, диалог удалён), после полного `fetch` уезжает в
`raw/вне-обхода/` и называется вслух. При `--only` сироты не трогаются: обход
неполон, и судить по нему нельзя.

**Негабарит.** День тяжелее потолка части нарезкой не делится (день целый по
устройству), и батч может выйти тяжелее безопасных `SAFE_TOKENS` (58 тысяч —
по замеру потолка вывода). Такие батчи `measure` называет отдельной главой:
на разборе их вывод может оборваться.

## Порядок работ: разбор батчей моделью

**Это платно.** Разбор батча — около сорока центов, проверка вторым агентом —
двадцать. Все 95 батчей — примерно 35–40 долларов.

```
python -m tgservice.voice прогон-все                      # весь порядок по всем батчам
python -m tgservice.voice прогон    --batch <файл>        # весь порядок на одном
python -m tgservice.voice разбор-все                      # только первый шаг по всем
python -m tgservice.voice verify --answer <файл> --batch <файл>   # сверка скриптом
python -m tgservice.voice переспрос --batch <файл>        # агент правит найденное
python -m tgservice.voice проверка  --batch <файл>        # второй агент читает разбор
python -m tgservice.voice дочистка-все --rounds 2         # круги переспроса до чистого
```

### Порядок на один батч

```
разбор → verify → если находки: переспрос → verify → проверка
```

`verify` денег не стоит и гоняется всегда; он же решает, нужен ли переспрос.
Уехавшую отметку он чинит молча (только однозначную — текст, встречающийся в
выгрузке один раз) и кладёт починенное обратно в разбор.

**Приговор «перегнать»** — латать дороже, чем купить заново: разбор
покупается второй раз, а старая заплатка и проверка сносятся (они написаны по
умершему тексту и вклеивали бы чужое). Второй раз «перегнать» — стоп: батч
остаётся неготовым и виден в «осталось», переспрос и проверка по мусору не
покупаются.

**Обрыв на потолке вывода** (`MAX_TOKENS`) — отказ, а не результат: разбор и
заплатка файлом не ложатся, свод уезжает в `*.обрыв.md` и готовым не
считается. Пустой ответ — то же самое (`analyse.Empty`).

**Готовое не покупается дважды.** Готовность — по файлам ответов: батч готов,
когда у него лежит непустая проверка. Убитый прогон продолжается с места
обрыва. `PROHIBITED_CONTENT` внутри прогона не пережидается, между прогонами
батч берётся снова.

### Сколько батчей идут одновременно

Шестнадцать, ключ `--workers`. Упирается в квоту Gemini, подбирается по
отказам 429. Голос каждого батча копится отдельно и выходит одним куском.
Ctrl+C сбрасывает очередь (`cancel_futures`) — летящие вызовы доедут, их
деньги уже потрачены.

### Сколько потрачено

Расход пишется по каждому шагу в `out/voice/answers/<батч>.расход.json` —
счётом модели, а не оценкой, с попытками и пустыми ответами. `analyse.bill()`
складывает всё; `прогон-все` называет итог последней строкой. Считать цену
надо по числу обращений, а не батчей: на батч их три, и вход переспроса с
проверкой больше, чем у разбора.

## Вторая половина: от разборов до скилла

CLI у этих шагов нет — запускаются из Python. Что за чем:

1. **Карточки и классификация.** `classify.cards` собирает карточку на
   каждого собеседника (портрет, блоки, счёт сообщений по выгрузке);
   `analyse.classify_all` раздаёт классы одним агентом (выделенные заданы
   решением владельца, `classify.apart`); `analyse.classify_check` проверяет
   вслепую судьями по сырой речи. Ничья «не отличить от: X» — своя корзина,
   не расхождение.
2. **Регистры.** `classify.registers` укрупняет классы по карте
   `регистры.json` — решение о сетке принимается по сходимости судей
   (18 классов дали 65%, 4 регистра — 82%).
3. **Порции и своды.** `classify.portions` режет разборы по регистрам с
   потолком по токенам; `analyse.merge_portion`/`merge_all` сводят порции;
   верхний свод собирается из нижних. Выделенные собеседники — своей веткой,
   в регистры не входят.
4. **Веса.** `classify.weights` считает по строкам «Сведён из», у скольких
   собеседников встретился блок, по цепочке через нижние своды.
5. **Сборка файла.** `compose.section` (разделы с весами и отказом на блоке
   без веса) → `compose.book` (общая шапка, таблица узнавания, решения
   владельца из `решения-по-классам.json`, числа корпуса параметром из
   замера, выделенные — параметром `отдельно`) → `compose.splitting`
   (дробление по блокам из `traits.turn_sizes`) → `analyse.impersonate`
   (обезличивание цитат агентом, вклейка `compose.replacements`/`impersonal`)
   → `compose.leaked` (страховка: имена собеседников по готовому файлу).
6. **Скилл.** `skillpack.pack(куда)` раскладывает `стиль.md` и файлы
   выделенных по `references/` скилла и называет вслух: устаревшие числа
   таблицы узнавания в SKILL.md, невклеенные решения владельца. Рукописные
   файлы (SKILL.md, FEEDBACK.md, правила.md) не трогает никогда.
7. **Замер.** `trial.case` собирает задание по обмену отложенной выборки
   (смысл даётся готовым через `analyse.meaning`, регистр агент берёт сам),
   `analyse.reply_as_owner` пишет ответ, признаки сравнивает скрипт, спорное
   судит агент по `замер-суд.md`.

### Выделенные собеседники

Один человек может давать больше половины всех сообщений владельца. Попав в
класс, он сделает класс своим портретом, а сведённый с остальными — превратит
свою манеру в манеру всех. Такого сводят своей веткой и кладут отдельным
файлом.

Кто выделен — решает владелец файлом `out/voice/решения-по-классам.json`,
ключ `__отдельно__`; читает его `classify.apart`:

```json
"__отдельно__": {
  "Имя как в карточке": {
    "класс": "какой класс ему назначен",
    "файл": "имя отдельного файла в out/voice и в references",
    "звать": "как назвать в файле стиля",
    "кто": "одна строка про роль",
    "доля": "60%"
  }
}
```

Второй способ — порог, в том же файле:

```json
"__порог__": 0.5
```

Доля сообщений владельца от 0 до 1. Все, кто выше, выделяются сами по
карточкам (`карточки.json`): класс «имя — отдельная категория», файл по имени,
доля посчитана. Названный поимённо старше автоматики — его класс и файл
берутся из записи. Дефолта в коде нет: нет порога — нет автоматики.

`classify_all` без параметра читает этот файл сам и считает доли по поданным
карточкам; `compose.book` берёт список `отдельно` и называет каждого в хвосте
файла стиля; `skillpack.pack` кладёт их файлы в `references/` и бережёт
названные в решениях, даже если на диске их в этот раз нет.

## Сверка выше батча

`verify.corpus()` собирает все батчи одной выгрузкой — секунда на сотне тысяч
сообщений. Нужна там, где у текста своего батча нет: цитату, сведённую из
многих чатов, по одному батчу не проверить. Имя батча перед цитатой снимает
`verify.unsourced`.

## Что знать про выгрузку

**Годовой обход — около сорока минут**; потолок чтения Телеграма — сотня
сообщений в секунду. Обход подаёт голос каждые пять тысяч сообщений.

**Убитый прогон продолжается с места обрыва.** Готовые чаты в
`out/voice/fetch_state.json`; состояние потеряно — готовое опознаётся по
самой выгрузке (кроме запуска с `--restart`).

**Окно ставится один раз и живёт в состоянии.** Считать его от «сегодня» на
каждом запуске нельзя: сутки дрейфа календаря не повод перечитывать год.

**Сессия одна на все задачи**, файл на запись пускает одного. Чужой процесс
убивать нельзя, шаг сам встаёт в очередь — замок ловится и в конструкторе
клиента.

**Группы берутся идентификаторами, а не именами**: имена повторяются
(«Цех», «Фотки» — по два-три чата). Кого взяли — `out/voice/groups_taken.json`.

## Оценка длины в токенах

`common.tokens` считает по родам знаков; коэффициенты измерены `countTokens`
(ошибка медианой 4%, смещения нет). Цифра стоит целый токен: штамп
`2025-09-24 14:28 ` — семнадцать токенов, слова «Вы как» — три. Поэтому дата
в батче стоит заголовком дня, а в строке — только время.

## Где что лежит

```

out/voice/fetch_state.json   что уже выгружено
out/voice/live_index.json    живые чаты, отсеянные и причины
out/voice/holdout.json|.md   отложенная выборка — НЕ ОТКРЫВАТЬ до замера
out/voice/batches/           батчи; batches_index.json — состав и размеры
out/voice/measure.json|.md   замер собранного, включая негабариты
out/voice/answers/           разборы, заплатки, проверки, расход по батчам
out/voice/карточки.json      карточки собеседников для классификации
out/voice/классы.json        роздано: имя → класс; классы.ответ.md — сырой ответ
out/voice/классы.проверка.json  итог судей: сошлось, разошлось, не различимо
out/voice/вердикты/          вердикт судьи по каждому проверенному чату
out/voice/регистры.json      карта класс → регистр
out/voice/регистры-решение.json  решение о сетке с числами сходимости
out/voice/решения-по-классам.json  решения владельца: переименования, правки к регистрам, __отдельно__
out/voice/порции-верх.json, порции-список.json  состав нарезки порций
out/voice/своды/             своды порций и итоговые по регистрам, свои ветки выделенных
out/voice/вес-блоков.json    веса блоков по регистрам
out/voice/стиль.md           собранный файл стиля; рядом — файлы выделенных из __отдельно__
out/voice/*.заплатка.md      оплаченные правки обезличивания
out/voice/*.до-обезличивания.md  снимки до вклейки — по ним проверяется чистка
out/voice/замер/             задания, ответы и вердикты замера по выборке
out/voice/probe/             образцы пробных прогонов на трёх устройствах батча
out/voice/tokens_real.json   замер оценщика токенов настоящим счётом
```

**Отложенную выборку трогать нельзя.** По ней проверяется файл стиля, и она
отделена до того, как хоть одна модель увидела материал.

**Личная переписка наружу не уходит.** Весь `out/` под гитигнором — и в любой
репозиторий, включая приватный, эти данные не заливаются.

## Правила, купленные ошибками

- **Маркер означает эффект, а не намерение.** «Файл есть» ≠ «в файле что-то
  есть»; «модель спрошена» ≠ «ответ применён».
- **Измеритель ломается чаще измеряемого.** Неправдоподобное число сперва
  проверяется вторым счётом, потом докладывается.
- **Формат читается по факту, а не по задуманному.** Агенты пишут заголовки,
  цитаты и пометки как угодно; разбор обязан понимать все виды — и быть
  один на всех читателей.
- **Измеримое считает скрипт точным правилом; неточно измеримое скрипту не
  поручается.** Дырявый список слов — суждение, выданное за счёт.
- **Функция без вызова — не починка.** Нужен тест на дорогу целиком.
- **Запасные пути (прерывание, возобновление, отказ) в бою не выполняются**
  и потому живут непроверенными, пока не стоят денег, — им нужны тесты.
